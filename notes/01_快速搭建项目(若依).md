## 4.若依框架

### 4.1.基本介绍

若依（RuoYi）框架是一款基于Spring Boot、Spring Cloud等开源框架搭建的企业级开发平台。它的主要目标是提供全面的解决方案，以简化企业级应用开发，提高开发效率。以下是对若依框架的详细介绍：

1. 模块化设计：若依框架采用模块化的设计，使得应用可以根据需求进行灵活的扩展和定制。每个模块都可以独立部署和升级，这大大提高了系统的可维护性和可扩展性。

2. 前后端分离：框架采用前后端分离的开发模式，后端专注于数据处理和API接口的提供，前端则负责页面的展示和用户交互。这种模式使得前后端职责明确，进一步提高了开发效率和代码的可维护性。

3. 权限管理：若依框架提供了完善的用户权限管理功能，包括角色管理、菜单授权、部门管理等，便于对系统权限进行灵活的配置和管理。

4. 代码生成器：框架内置代码生成器，能够快速生成前后端代码，减少重复劳动，提高开发效率。通过简单的配置即可生成基础的增删改查代码。

5. 定时任务：若依框架集成了定时任务模块，支持动态添加定时任务，可以通过界面对定时任务进行管理与调度。此外，框架还能实时查看系统运行日志和在线用户信息，监控服务状态和性能。

6. 易于集成：若依框架可以轻松地与其他常用技术栈集成，如Mysql、Redis、消息队列等。这使得开发者可以根据项目需求灵活地选择合适的技术组件，降低技术门槛和成本。

此外，若依框架还集成了许多常用功能模块，如文件上传下载、消息推送、数据字典、日志管理等。

总的来说，若依框架是一款功能丰富、易于扩展和定制的企业级开发平台，适用于各种Web应用程序的开发。它能够帮助开发者快速构建功能完备的应用，提高开发效率，降低维护成本。

### 1.1.安装Mysql

服务器启动之后，执行以下创建容器的脚本\(虚拟机已经提供好,不需要执行\)

```bash
docker run -p 3306:3306  \
--restart=always   \
--name  mysql \
-e MYsql_ROOT_PASSWORD=heima123 \
-e TZ=Asia/Shanghai \
-v /usr/local/mysql/data:/var/lib/mysql \
-v /usr/local/mysql/conf:/etc/mysql/conf.d \
-d mysql:8.0.29 \
--lower-case-table-names=1
```

> - `-d`: 表示以后台模式运行容器。
> 
> - `-p`: 将容器的3306端口映射到宿主机的3306端口。
> 
> - `--restart=always`: 即当Docker服务重启或容器异常退出时，容器会自动重启。
> 
> - `-e MYsql_ROOT_PASSWORD=heima123`: Mysql的root用户的密码。
> 
> - `--lower-case-table-names=1`: 设置Mysql以忽略表名的大小写。值为1表示所有表名在文件系统中都以小写存储，适用于Windows和Mac OS系统
>

修改父工程`xhzb`的pom文件，方便对新创建的模块进行管理

```xml
<!-- 依赖声明 -->
<dependencyManagement>
    <dependencies>

        <!-- 其他配置略 -->

        <!-- 养老项目专用模块 -->
        <dependency>
            <groupId>com.xhzb</groupId>
            <artifactId>xhzb-nursing-platform</artifactId>
            <version>${xhzb.version}</version>
        </dependency>

    </dependencies>
</dependencyManagement>
```

在新创建的模块`xhzb-nursing-platform`中新增以下依赖，方便间接依赖spring、mysql等依赖

```xml
<dependencies>
    <dependency>
        <groupId>com.xhzb</groupId>
        <artifactId>xhzb-framework</artifactId>
    </dependency>
</dependencies>
```

该项目的入口模块为`xhzb-admin`，新增的业务模块需要让被`xhzb-admin`依赖才能生效，在`xhzb-admin`中的pom文件中新增`xhzb-nursing-platform`的依赖

```xml
<!-- 养老模块 -->
<dependency>
    <groupId>com.xhzb</groupId>
    <artifactId>xhzb-nursing-platform</artifactId>
</dependency>
```

注意事项：修改了任意模块的pom文件，都别忘了刷新maven，不然不生效

```java
import com.xhzb.common.core.domain.AjaxResult;

import com.xhzb.nursing.service.INursingProjectService;

import com.xhzb.common.core.page.TableDataInfo;

/**
 * 护理项目Controller
 * 
 * @author ruoyi
 * @date 2026-03-05
 */
@RestController
@RequestMapping("/nursing/project")
public class NursingProjectController extends BaseController
{
    @Autowired
    private INursingProjectService nursingProjectService;

    /**
     * 查询护理项目列表
     */
    @PreAuthorize("@ss.hasPermi('nursing:project:list')")
    @GetMapping("/list")
    public TableDataInfo list(NursingProject nursingProject)
    {
        startPage();
        List<NursingProject> list = nursingProjectService.selectNursingProjectList(nursingProject);
        return getDataTable(list);
    }

    /**
     * 导出护理项目列表
     */
    @PreAuthorize("@ss.hasPermi('nursing:project:export')")
    @Log(title = "护理项目", businessType = BusinessType.EXPORT)
    @PostMapping("/export")
    public void export(HttpServletResponse response, NursingProject nursingProject)
    {
        List<NursingProject> list = nursingProjectService.selectNursingProjectList(nursingProject);
        ExcelUtil<NursingProject> util = new ExcelUtil<NursingProject>(NursingProject.class);
        util.exportExcel(response, list, "护理项目数据");
    }

    /**
     * 获取护理项目详细信息
     */
    @PreAuthorize("@ss.hasPermi('nursing:project:query')")
    @GetMapping(value = "/{id}")
    public AjaxResult getInfo(@PathVariable("id") Long id)

        return success(nursingProjectService.selectNursingProjectById(id));
    }

    @PreAuthorize("@ss.hasPermi('nursing:project:add')")
    @Log(title = "护理项目", businessType = BusinessType.INSERT)
    @PostMapping
    public AjaxResult add(@RequestBody NursingProject nursingProject)

    }

    /**
     * 修改护理项目
     */
    @PreAuthorize("@ss.hasPermi('nursing:project:edit')")
    @Log(title = "护理项目", businessType = BusinessType.UPDATE)
    @PutMapping
    public AjaxResult edit(@RequestBody NursingProject nursingProject)
    {
        return toAjax(nursingProjectService.updateNursingProject(nursingProject));
    }

    /**
     * 删除护理项目
     */
```

# 六、在线接口文档

刚才我们测试都是基于前端项目完成的，如果后期开发中，前端还未开发完成，我们也需要对于后端的接口来进行测试，这个怎么做呢？

现在如果我们与前端对接，需要提供详细的接口文档才行，不过在开发的过程中，接口文档可能不能及时的提供，或者是更新不及时，就会造成信息闭塞，造成不必要的效率降低。

所以，一般的前后端分离的项目，都会采用在线的接口工具进行调试，可以实时的展示接口的详细数据，也可以很方便的对接口进行测试。

## 1.Swagger介绍

Swagger 是一个规范和完整的框架，用于生成、描述、调用和可视化 RESTful 风格的 Web 服务

官网：https://swagger.io/autolink

它的主要作用是：

- 使得前后端分离开发更加方便，有利于团队协作

- 接口的文档在线自动生成，降低后端开发人员编写接口文档的负担

- 功能测试 

Spring已经将Swagger纳入自身的标准，建立了Spring\-swagger项目，现在叫Springfox。通过在项目中引入Springfox ，即可使用Swagger。

Springfox（Swagger 2） 已停止维护，不兼容 Spring Boot 3/4。

Spring Boot 4 必须使用 springdoc\-openapi v3\.x，v2\.x 仅支持 Spring Boot 3\.x。

访问地址：

- OpenAPI 文档：`/v3/api-docs`

```typescript
package com.xhzb.web.core.config;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import com.xhzb.common.config.RuoYiConfig;
import io.swagger.v3.oas.models.Components;
import io.swagger.v3.oas.models.OpenAPI;
import io.swagger.v3.oas.models.info.Contact;
import io.swagger.v3.oas.models.info.Info;
import io.swagger.v3.oas.models.security.SecurityRequirement;
import io.swagger.v3.oas.models.security.SecurityScheme;

/**
 * Swagger3 (OpenAPI 3.0) 接口文档配置类
 * <p>
 * 用于配置和管理系统的 API 接口文档，提供以下功能：
 * <ul>
 *   <li>配置 API 文档的基本信息（标题、描述、版本等）</li>
 *   <li>设置接口的认证机制（Bearer Token）</li>
 *   <li>生成可视化的接口文档页面</li>
 * </ul>
 * </p>
 * 
 * @author ruoyi
 * @see io.swagger.v3.oas.models.OpenAPI
 */
@Configuration
public class SwaggerConfig
{
    /** 系统基础配置，包含应用名称和版本等信息 */
    @Autowired
    private RuoYiConfig ruoyiConfig;
    
    /**
     * 创建自定义的 OpenAPI 配置对象
     * <p>
     * 该方法配置了：
     * <ul>
     *   <li>安全认证方案（API Key + Bearer Token）</li>
     *   <li>全局安全要求（所有接口默认需要认证）</li>
     *   <li>API 基本信息（标题、描述、联系人、版本）</li>
     * </ul>
     * </p>
     *
     * @return OpenAPI 配置对象，包含完整的 API 文档配置信息
     */
    @Bean
    public OpenAPI customOpenApi()
    {
        return new OpenAPI().components(new Components()
            // 设置认证的请求头，定义 API Key 的安全方案
            .addSecuritySchemes("apikey", securityScheme()))
            // 为所有接口添加全局安全要求，使用 apikey 进行认证
            .addSecurityItem(new SecurityRequirement().addList("apikey"))
            // 设置 API 文档的基本信息
            .info(getApiInfo());
    }
    
    /**
     * 创建安全认证方案配置
     * <p>
     * 配置基于 JWT Token 的认证方式：
     * <ul>
     *   <li>类型：API Key</li>
     *   <li>参数名：Authorization</li>
     *   <li>传递位置：HTTP Header</li>
     *   <li>认证方案：Bearer</li>
     * </ul>
     * </p>
     * <p>
     * 客户端调用接口时需要在请求头中添加：
     * {@code Authorization: Bearer <your_jwt_token>}
     * </p>
     *
     * @return SecurityScheme 安全认证方案对象
     */
    @Bean
    public SecurityScheme securityScheme()
    {
        return new SecurityScheme()
            // 设置认证类型为 API Key
            .type(SecurityScheme.Type.APIKEY)
            // 设置请求头参数名称为 Authorization
            .name("Authorization")
            // 设置参数传递位置为 HTTP Header
            .in(SecurityScheme.In.HEADER)
            // 设置认证方案为 Bearer
            .scheme("Bearer");
    }
    
    /**
     * 构建 API 文档的基本信息
     * <p>
     * 包含以下信息：
     * <ul>
     *   <li>标题：若依管理系统_接口文档</li>
     *   <li>描述：系统功能模块说明</li>
     *   <li>联系人：从配置中读取的应用名称</li>
     *   <li>版本：从配置中读取的应用版本号</li>
     * </ul>
     * </p>
     *
     * @return Info 对象，包含 API 文档的元数据信息
     */
    public Info getApiInfo()
    {
        return new Info()
            // 设置 API 文档标题
            .title("标题：若依管理系统_接口文档")
            // 设置 API 文档描述信息
            .description("描述：用于管理集团旗下公司的人员信息,具体包括XXX,XXX模块...")
            // 设置作者/联系人信息，从 RuoYiConfig 中获取应用名称
```

## 4.项目中使用

如果现在想要测试护理项目，我们发现在swagger中并没有护理项目相关的接口，如果想要展示这些接口，我们需要添加上必要的注解来进行说明才能阅读和访问。

### 4.1.常见注解

通过注解可以控制生成的接口文档，使接口文档拥有更好的可读性，常用注解如下：

|老 Swagger2（已废弃）|新 OpenAPI3|说明|
|---|---|---|
|@Api|@Tag|用在类上，描述Controller的作用|
|@ApiOperation|@Operation|用在方法上，说明方法的用途、作用|
|@ApiParam|@Parameter|用在方法的参数上，描述单个形参的含义|
|@ApiImplicitParam|@Parameter|用在方法上，描述单个形参的含义，与上面相比使用范围更广|
|@ApiModel|@Schema|用在类上，用对象来接收参数或者返回参数，描述类的含义|
|@ApiModelProperty|@Schema|用在类的属性上，用对象来接收参数或者返回参数，描述字段的含义|

### 4.2.Controller的方法参数说明

我们熟悉了这些注解之后，我们可以让AI协助我们快速完成注解的编写：
